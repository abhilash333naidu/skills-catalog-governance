# V2.0 Quickstart

V2.0 governs one generated skill at a time. It accepts a versioned proposal, keeps it
quarantined, records read-only evidence, requires a human decision, and activates only
with explicit confirmation.

V2.0 is a local proposal/adapter contract. It does not intercept undocumented Hermes
internals, invoke an LLM, execute generated skill content, merge skills, or activate
skills automatically.

## 1. Capture A Hermes Proposal

For an actual Hermes agent-created skill, create a capture bundle from Hermes' skill
file, `.usage.json` record, and a separately captured Hermes identity record:

```bash
python3 scripts/catalog_governance.py capture-hermes \
  --skill-dir /path/to/hermes/skills/<skill-name> \
  --usage /path/to/hermes/skills/.usage.json \
  --metadata /path/to/hermes-capture.json \
  --active-root /path/to/active/skills \
  --output /path/to/capture-bundle
```

The adapter emits `proposal.json`, `receipt.json`, and copied source evidence. It
requires the native Hermes `created_by: "agent"` usage marker and refuses supporting
payload files in the current single-file V2 path. Capture metadata must include Hermes
version, commit, session, and timestamp; task and write-origin context are optional.
See [`docs/hermes-capture.md`](hermes-capture.md).

For a manual adapter integration, prepare a `SKILL.md` and a matching `proposal.json`
containing:

- `schema: skill-proposal-1`
- `proposal_id`
- generator and source-session provenance
- exact `skill_sha256`
- declared capabilities
- `requested_action: CREATE`
- one `target.active_root`

The proposal target name must match the skill frontmatter name.

## 2. Intake

```bash
python3 scripts/catalog_governance.py intake \
  --skill ./generated/SKILL.md \
  --provenance ./generated/proposal.json \
  --root ./skill-governance \
  --active-root /path/to/active/skills
```

Expected status: `QUARANTINED`.

Intake never writes to the active skill root. Repeating the same proposal and hash is
idempotent. A changed hash, proposal-ID collision, unsafe root, non-empty payload, or
attempted auto-approval fails closed.

## 3. Evaluate And Inspect Impact

```bash
python3 scripts/catalog_governance.py evaluate-proposal \
  --proposal ./skill-governance/quarantine/<proposal-id> \
  --root ./skill-governance \
  --active-root /path/to/active/skills

python3 scripts/catalog_governance.py impact-report \
  --proposal ./skill-governance/quarantine/<proposal-id> \
  --active-root /path/to/active/skills \
  --scan-root /path/to/active/skills \
  --scan-root /path/to/config
```

Evaluation writes `validation.json`, `capabilities.json`, and `impact.json`. Capability
classification is heuristic textual signal detection, not proof of runtime behavior.
Impact output lists both `searched_roots` and `unscanned_roots`.

## 4. Validate Policy And Decide

Use a policy with human approval required and automatic approval/merge disabled:

```bash
python3 scripts/catalog_governance.py check-policy \
  --policy ./skill-governance/policy.json

python3 scripts/catalog_governance.py decide \
  --proposal ./skill-governance/quarantine/<proposal-id> \
  --root ./skill-governance \
  --policy ./skill-governance/policy.json \
  --decision APPROVE \
  --actor local-user \
  --text "Reviewed the recorded evidence" \
  --output ./skill-governance/decisions/<proposal-id>.json
```

The decision binds the proposal hash, policy hash, evidence hash, actor, and decision
text. Evaluation success never implies approval.

## 5. Activate

```bash
python3 scripts/catalog_governance.py activate \
  --proposal ./skill-governance/quarantine/<proposal-id> \
  --root ./skill-governance \
  --active-root /path/to/active/skills \
  --policy ./skill-governance/policy.json \
  --decision ./skill-governance/decisions/<proposal-id>.json \
  --apply --yes
```

Expected status: `ACTIVE`.

Activation is create-only, one-root, non-overwriting, and hash-bound. It creates an
explicit snapshot and active record. If a later activation step fails, the command
returns `ACTIVATION_FAILED` and removes the newly published target only when its content
still matches the hash published by that invocation.

## 6. Verify And Roll Back

```bash
python3 scripts/catalog_governance.py verify-active \
  --record ./skill-governance/active-records/<proposal-id>.json

python3 scripts/catalog_governance.py rollback \
  --record ./skill-governance/active-records/<proposal-id>.json \
  --root ./skill-governance \
  --apply --yes
```

Verification reports `CLEAN` or `DRIFTED`. Rollback refuses active drift and reports
`RESTORED` only after removing the newly activated CREATE target and preserving an
archived copy.

## Current Limitations

- No native Hermes admission hook has been verified.
- No update, replacement, retirement, automatic merge, or automatic activation path.
- No background watcher or daemon.
- No crash-atomic guarantee across every multi-file filesystem operation.
- No comprehensive malicious-skill or prompt-injection scanner.
- Real Hermes adapter and Windows junction fixtures remain follow-on validation work.
